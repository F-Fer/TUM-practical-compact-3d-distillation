# Knowledge base: what we tried, what worked, how well

Read this first, before planning or running any experiment. One file per idea in [ideas/](ideas/), sorted by question
rather than by session; the session reports (`results/pba/REPORT*.md` etc.) stay the long-form evidence and are cited
by section. Updated 2026-11-10.

- [evaluation.md](evaluation.md): scene sets, noise levels, timing conventions and evaluation pitfalls. Needed to read
  any number here.
- [runs.csv](runs.csv): one row per scored run on this machine (~950: PBA, track BA, feed-forward, views), generated by
  `scripts/index_runs.py`. Grep it before running a configuration: `grep -i "lm_photo_loss=ncc" knowledge/runs.csv`.
- [infrastructure.md](infrastructure.md): tum2/job/disk lessons.

## Workflow

**Before an experiment:** read this page, grep `ideas/` and `runs.csv` for the idea and its options. If it was tried,
the idea file says on which configuration, set and seeds, and whether a later change could alter the answer.

**After an experiment** (also after a negative or inconclusive one):
1. Update the idea file (or create one from the template below): a row in its evidence table with date, setting
   (model, set, seeds, baseline, code path), change, result, source; then update its status line and answer if they
   changed. Mark what it supersedes, don't delete it.
2. Update this README if the current best, a status in the index or the open questions changed.
3. Copy configs + metric JSONs of runs worth keeping to `results/pba/runs/<model>/<run>/` (local, not in git; scratch
   is auto-deleted after 30 days), then `.venv/bin/python scripts/index_runs.py`.
4. Long write-ups still go into a report; the idea files link to it.

Idea file template:

```markdown
# <question or idea>
Status: adopted | rejected | open | partly (<what>) | superseded by <file> · Area: ... · Updated YYYY-MM-DD
**Answer:** one to three sentences, with the key numbers and the set they're on.
## Evidence
| date | setting (model, set, seeds, baseline) | change | result | source (report §, run names) |
## Open / don't repeat
Related: [other](other.md)
```

## Current best (2026-11-10)

**Dev** (22 scenes, one seed, RTX 5090, compute plot `results/pba/figures5/compute_all_models.png`): AUC@3 / F1 (4 sets)
at total seconds per scene (DA3 forward + TTO). Configurations in [pba-method](ideas/pba-method.md).

| model | DA3 alone | cheapest good: photometric T = 25 | best pose | best F1 |
|---|---|---|---|---|
| SMALL | 16.2 / 31.5, 0.40 s | 43.8 / 46.8, 0.71 s | 55.6, photometric + 40 LM on NCC, T = 800, 5.1 s | 53.1 (same run) |
| BASE | 27.1 / 44.7, 0.85 s | 59.2 / 62.8, 1.11 s | 64.8, NCC config T = 800, 5.6 s | 63.8, photometric T = 200, 1.8 s |
| LARGE-1.1 | 48.6 / 59.9, 1.60 s | 71.0 / 70.4, 1.83 s | 74.1, VGG + NCC T = 800, 17.2 s (72.9 NCC config T = 200, 3.4 s) | 72.0, VGG + Huber T = 400, 4.1 s |
| GIANT-1.1 | 67.8 / 73.5, 3.10 s | 74.9 / 76.1, 3.32 s | 77.2, VGG + NCC T = 25, 4.0 s | 77.0, VGG + Huber T = 50, 3.7 s |

**Held-out** (59 scenes, one seed): SMALL alone 13.6 → B′ T = 50 44.0 → NCC config with shared focal **57.2** (F1 57.0,
4.8 s TTO); BASE 27.0 → 57.4 → **68.3**; LARGE-1.1 52.0 → 69.7 → **74.8**; GIANT no held-out run. Track BA has no
held-out run. DéjàView K = 12 alone: 58.7 AUC@3 on the full benchmark at 0.96 s.

**Project question** ([matched-compute](ideas/matched-compute.md)): at matched time a model + photometric TTO now beats
the next larger model alone for SMALL→BASE and BASE→LARGE (held-out too), and LARGE→GIANT on pose only.

## Open questions, roughly by value

1. Held-out tests of the current configurations on GIANT and of the VGG configurations with the shared focal.
2. Why NCC helps ETH3D/DTU (the loss or its 4,096 samples) and a stop rule for the NCC LM ([ncc](ideas/ncc.md)).
3. Information for the weak pose directions: a wide-baseline term or tracks on top of B′
   ([pose prior](ideas/pose-prior-and-flat-directions.md), [correspondences](ideas/correspondences-in-pba.md)).
4. TTO on DéjàView with fewer steps ([dejaview-steps](ideas/dejaview-steps.md), Antonin's jobs).
5. One vs two radial coefficients in the same configuration on all 11 ETH3D scenes ([radial](ideas/radial-lens-model.md)).
6. Track BA rerun with the shared focal / current polish, so it can be compared fairly ([track-ba](ideas/track-ba.md)).
7. Re-tune the per-model priors (`w_prior`, `w_pose`) on the current configurations; GIANT never had any prior.
8. DTU focal drift and the DTU radial coefficient (−0.22) that looks like it absorbs another error.
